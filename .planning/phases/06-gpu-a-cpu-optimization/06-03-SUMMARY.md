# Phase 6 Plan 3: ONNX Export & INT8 Quantization Summary

ONNX export pipeline with INT8 dynamic quantization and inference factory for automatic CPU/GPU backend routing.

## What Was Done

### Task 1: ONNX Export Script and INT8 Quantization
- Created `backend/scripts/export_onnx.py` — standalone export script
  - Loads PyTorch AST checkpoint, exports via `torch.onnx.export()` (opset 14)
  - Applies dynamic INT8 quantization with per-channel QInt8
  - Validates with `onnx.checker.check_model()`
  - Reports compression ratio and accuracy comparison (atol=0.1)
  - Runnable via `cd backend && python -m scripts.export_onnx`
- Added `onnxruntime>=1.18.0` and `onnx>=1.16.0` to requirements.txt
- Added `AST_ONNX_MODEL_PATH` to config Settings

### Task 2: ONNX Inference Service and Inference Factory
- Created `ASTInferenceONNXService` — drop-in replacement for CPU inference
  - Same interface as `ASTInferenceService` (load_model, predict_segment, predict_batch)
  - Uses `ort.InferenceSession` with CPUExecutionProvider, 2 threads
  - Startup benchmark compares ONNX INT8 vs eager PyTorch latency
  - Logs speedup ratio with warning if below 3x target
- Created `inference_factory.py` with `create_inference_service()`
  - GPU available: always PyTorch (GPU faster than ONNX CPU)
  - CPU + ONNX model: ONNX INT8 with try/except fallback
  - CPU + no ONNX: eager PyTorch fallback
  - Logs selected backend and reason
- Updated `get_ast_inference_service()` singleton to use factory

## Deviations from Plan

None - plan executed exactly as written.

## Decisions Made

1. **Manual torch.onnx.export over optimum**: AST model is straightforward, avoids heavy HuggingFace optimum dependency
2. **Factory with lazy imports**: Each backend imported only when selected, avoiding import errors on systems missing onnxruntime
3. **Benchmark at load time**: ONNX service benchmarks against temporary PyTorch instance on first load, then discards it
