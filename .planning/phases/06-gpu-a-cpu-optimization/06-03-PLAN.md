  <name>Task 1: ONNX export script and INT8 quantization</name>
  <files>backend/scripts/export_onnx.py, backend/requirements.txt, backend/app/config.py</files>
  <action>
**requirements.txt:** Add `onnxruntime>=1.18.0` and `onnx>=1.16.0`. Do NOT add optimum — use manual torch.onnx.export instead (simpler, AST model is straightforward, avoids heavy dependency).

**config.py:** Add `AST_ONNX_MODEL_PATH: Path = RECOGNITION_MODELS_FOLDER / "ast_active_int8.onnx"` to Settings class.

**backend/scripts/export_onnx.py:** Create standalone export script that:
1. Loads the PyTorch AST model from `settings.AST_MODEL_PATH`
2. Creates dummy input tensor (1, 1024, 128) on CPU
3. Exports via `torch.onnx.export()` with:
   - opset_version=14
   - input_names=["input_values"]
   - output_names=["logits"]
   - dynamic_axes={"input_values": {0: "batch"}, "logits": {0: "batch"}}
4. Applies dynamic INT8 quantization via `onnxruntime.quantization.quantize_dynamic`:
   - weight_type=QuantType.QInt8
   - per_channel=True
   - optimize_model=True
5. Validates the quantized model with `onnx.checker.check_model()`
6. Logs file sizes (original vs INT8) and reports compression ratio
7. Runs accuracy comparison: feed same dummy input to both PyTorch and ONNX, check logits are close (atol=0.1)

Script should be runnable via: `cd backend && python -m scripts.export_onnx`

Add `if __name__ == "__main__":` block. Use argparse for optional `--model-path` override.
  </action>

  </verify>

5. If CPU only AND no ONNX model: use ASTInferenceService (eager PyTorch as fallback)
6. Log which backend was selected and why
