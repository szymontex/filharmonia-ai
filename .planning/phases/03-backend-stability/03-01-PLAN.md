<task type="auto">
  <name>Task 2: Create JobRegistry service</name>
  <files>backend/app/services/job_registry.py</files>
  <action>
Create `backend/app/services/job_registry.py` with:

1. SQLite schema:
   - jobs table: job_id (TEXT PRIMARY KEY), job_type (TEXT), status (TEXT), data (TEXT JSON), created_at, updated_at
   - Index on status and created_at

2. JobRegistry class:
   - `__init__(db_path: Path)` - store path, create TTLCache(maxsize=1000, ttl=3600)
   - `async initialize()` - create tables if not exist, enable WAL mode
   - `async create_job(job_id, job_type, initial_data)` - insert to DB, populate cache
   - `async get_job(job_id)` - cache-first read, fallback to DB
   - `async update_job(job_id, updates)` - merge updates, write to both cache and DB
   - `async list_jobs(status=None, limit=100)` - list recent jobs
   - `async cleanup_old_jobs(days=7)` - delete jobs older than N days

3. Singleton pattern:
   - `_registry: Optional[JobRegistry] = None`
   - `async get_job_registry() -> JobRegistry` - lazy init singleton
   - Store DB at `settings.FILHARMONIA_BASE / '.claude' / 'jobs.db'`

4. Thread safety:
   - Use `asyncio.Lock()` for write operations (SQLite single-writer lock)
   - TTLCache access via asyncio (no threading lock needed in async context)

Reference patterns from 03-RESEARCH.md "Pattern 1: TTL-Based In-Memory Cache with SQLite Backing" and "Complete Job Registry Service" code example.
  </action>
